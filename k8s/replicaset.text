A ReplicaSet in Kubernetes ensures that a specified number of identical Pods are always running. If a Pod crashes or is deleted, the ReplicaSet automatically creates a new one.



What is ReplicaSet?

Maintains desired number of Pods
Uses labels & selectors to manage Pods
Part of higher-level controllers like Deployment


Key Fields Explained

replicas → number of Pods you want
selector → matches labels of Pods
template → blueprint of Pods



ReplicaSet Commands (Most Important 🚀)
  
  1. Create ReplicaSet
  
    kubectl apply -f replicaset.yaml


Get ReplicaSets
  
  kubectl get rs



Describe ReplicaSet
  
  kubectl describe rs my-replicaset


Check Pods created by ReplicaSet
  
  kubectl get pods

Scale ReplicaSet

  Method 1 (imperative)
    
    kubectl scale rs my-replicaset --replicas=5


Method (edit YAML)
    
    kubectl edit rs my-replicaset

Delete ReplicaSet
    
    kubectl delete rs my-replicaset


Delete ReplicaSet WITHOUT deleting Pods
  
  kubectl delete rs my-replicaset --cascade=orphan



Update ReplicaSet (image change)
    
    kubectl set image rs/my-replicaset nginx=nginx:latest


Explain ReplicaSet (very useful in interviews)
  
  kubectl explain rs




Feature               Pod                        ReplicaSet 

Type                    Resource                    Controller

Purpose                 Run container               Maintain Pods

Self-healing            No                          Yes

Scaling                 Manual                      Automatic

Use in Prod             Rare                        Indirect (via Deployment)

Failure Case            Pod dies → stays dead       Pod dies → recreated







apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: nginx-rs
  namespace: prod
spec:
  replicas: 2
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-svc
  namespace: prod
spec:
  type: NodePort
  selector:
    app: nginx
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080
